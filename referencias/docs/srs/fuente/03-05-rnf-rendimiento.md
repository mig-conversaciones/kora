## 3.6 Rendimiento, capacidad, SQL, caché y pruebas de carga (RNF-PERF)

La capacidad se comprueba para una versión, una infraestructura, un volumen de datos y un perfil de uso concretos. No se asume que la aplicación falle por haber sido creada con IA, ni se promete capacidad por añadir índices, caché o colas. Los valores son metas PENDIENTES DE VALIDACIÓN (S-07 y S-08) y sin ejecución verificable su estado es PENDIENTE DE EJECUCIÓN.

**Objetivos por flujo (p95 medido en el servidor desde k6 externo):**

| Flujo | p95 objetivo | Errores inesperados | Notas |
|---|---|---|---|
| Inicio de sesión (POST con Argon2id) | 900 ms o menos | Menos de 0,5 % | Dominado por el costo de Argon2id (RAC-002) |
| Tablero central o técnico (página completa) | 1.200 ms o menos con caché fría; 500 ms o menos con caché caliente | Menos de 0,5 % | Con el dataset de 3 años (RNF-PERF-016) |
| Fragmento de filtros del tablero (HTMX) | 800 ms o menos fría; 350 ms o menos caliente | Menos de 0,5 % | Solo la sección afectada |
| Listado paginado con búsqueda (25 filas) | 600 ms o menos | Menos de 0,5 % | Orden y filtros en servidor |
| Guardar formulario (crear o editar) | 700 ms o menos | Menos de 0,5 % | Incluye validación, auditoría e invalidación de caché |

| Exportación PDF del tablero | 3 min o menos | — | Desde la solicitud hasta el archivo disponible |
| Correo transaccional en el SMTP | 3 min o menos | — | Desde el encolado |
